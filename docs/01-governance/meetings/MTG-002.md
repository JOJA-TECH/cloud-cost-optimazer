## Objetivo

Definir las tareas para el primer avance, repartir responsabilidades iniciales, establecer prioridades del documento y acordar la comunicación con el profesor antes de la entrega formal.

## Agenda

1. Revisión de la entrega beta al profesor.
2. Distribución de tareas técnicas y documentales.
3. Definición inicial de datos, frontend y arquitectura de persistencia.
4. Identificación de pendientes y criterios de entrega.

## Temas tratados

### Entrega académica

Se acordó entregar al profesor una versión beta con el avance disponible hasta la sección de usuarios, clientes y partes interesadas. El equipo buscará retroalimentación antes de la fecha formal de entrega. La primera entrega prioriza planteamiento del problema, justificación, objetivos, usuarios beneficiados, alcance y antecedentes.

### Organización del trabajo

Se ratificó el sprint o retrospectiva de los domingos a las 10:00 a. m. Quedó pendiente organizar formalmente las tareas específicas de todos los integrantes.

### Arquitectura de datos

Se acordó separar la persistencia en dos bases de datos: una para la comunicación entre el usuario y la aplicación, y otra para el módulo de inteligencia artificial, la recolección de datos y futuros entrenamientos. La implementación inicial será local con PostgreSQL.

### Frontend y datos visualizados

El frontend deberá incluir una landing page y una aplicación con inicio de sesión. El usuario podrá consultar sus recursos, seleccionar uno y revisar métricas, estadísticas y sugerencias. La interfaz deberá comparar el costo actual con el costo estimado de aplicar una recomendación. El sistema solo sugerirá cambios; no los aplicará automáticamente.

### Rendimiento esperado

Se mencionó como meta que el flujo de análisis y recomendación genere resultados en menos de 30 segundos. La métrica debe precisarse posteriormente mediante una definición de inicio, fin, condiciones de prueba y percentil de cumplimiento.

## Decisiones tomadas

- **DEC-021:** Entregar una versión beta al profesor antes de la entrega formal para recibir retroalimentación.
- **DEC-022:** Separar la persistencia en una base de aplicación y una base de datos para inteligencia artificial y recolección.
- **DEC-023:** Utilizar PostgreSQL local durante la fase inicial.
- **DEC-024:** Mantener la aplicación como sistema de recomendación; no ejecutar cambios automáticamente.
- **DEC-025:** Priorizar la primera entrega académica antes de completar las secciones técnicas restantes.
- **DEC-026:** Mantener el sprint o retrospectiva los domingos a las 10:00 a. m.

La decisión DEC-022 tiene impacto arquitectónico y se documenta también en ADR-002.
